# craftlight

*[English version →](README.md)*

Дисциплинированный процесс разработки для Claude Code в одном плагине. Общий принцип всех навыков: **церемония пропорциональна задаче** — по умолчанию начинаем налегке, эскалируем только по явным наблюдаемым сигналам. Главный враг — впустую сожжённые токены: субагенты, перечитывающие контекст, и слепые циклы «поправил наугад — перезапустил».

## Установка

```bash
claude plugin marketplace add progiri/craftlight
claude plugin install craftlight@craftlight
```

В интерактивном Claude Code — те же команды через `/plugin marketplace add …` и `/plugin install …`.

> Имя маркетплейса (`craftlight`) берётся из `marketplace.json`, а не из имени репозитория.

## Внедрение в существующий проект

Ничего не нужно настраивать заранее — дисциплина нарастает по ходу работы:

1. **Установите плагин** (команды выше) — и просто ставьте задачи как обычно.
2. **Первый вызов любого навыка** вставляет управляемый блок в сам `CLAUDE.md` (ваш текст вне маркеров не трогается).
3. **Первая задача уровня M/L** бутстрапит `CRAFT.md`: секцию «Что это» (описание проекта) + карту. Спеки, брифы и бэклог появятся в `docs/crafts/` по мере работы.
4. **Опционально, для большого legacy**: скажите «внедрить craftlight» / «засеять граф поверх legacy» — навык `craft-graph` (full) сразу задокументирует существующие решения и ловушки как узлы с пруфами `файл:строка`, не дожидаясь первых wrap'ов.

Не создавайте `docs/graph/` и `CRAFT.md` руками заранее: пустой узел хуже его отсутствия, а карта до первой задачи — это карта, построенная по README.

## Что внутри

Шесть навыков, объединённых одной дисциплиной и общей «зоной риска» (авторизация, деньги, миграции, конкурентность, удаление данных).

**Самоподдержка CLAUDE.md.** При первом запуске любого навыка в проекте craftlight настраивает минимальный управляемый блок в корневом `CLAUDE.md` (в маркерах `craftlight:start/end` + версия): какой навык когда, старт с `CRAFT.md`, неотменяемые инварианты. Так дисциплина оказывается в контексте ещё до срабатывания навыков. Блок идемпотентен, обновляется по версии и не трогает ваш текст вне маркеров. Референс — [`skills/task/templates/CLAUDE-block.md`](plugins/craftlight/skills/task/templates/CLAUDE-block.md).

### `task` — роутер для задач на изменение кода

Точка входа для любой работы, меняющей код. Классифицирует задачу и загружает плейбук режима:

| Режим | Артефакты | Когда |
|---|---|---|
| **S** | нет — сразу код + 1 атомарный коммит | 1–2 файла, однозначные критерии, тривиальный откат |
| **M** | один `SPEC.md` в `docs/crafts/<slug>/` | 3–10 файлов, открытые вопросы, нужна аккуратность |
| **L** | `SPEC.md` с фазами + внешняя память | >10 файлов, архитектурные решения, миграции |

Зона риска → минимум M даже для однострочного изменения. Эскалация дешёвая и разрешена в любой момент; деэскалация одна (M→S) и никогда не обходит защиту зоны риска. `SPEC.md` (в `docs/crafts/<slug>/`) едет вместе с git-веткой — это трекер состояния и механизм возобновления. Запрет на guess-and-patch и тихое расползание скоупа; замеченное по пути чужое не теряется и не просачивается в код — одна строка в `docs/crafts/_backlog.md` (сток, а не трекер; триаж — дело человека).

task также владеет **`CRAFT.md`** — картой проекта в корне репозитория, точкой старта после CLAUDE.md (секция «Что это» — плотное описание проекта, точки входа, карта модулей, указатели в граф). Он бутстрапит её на первом M/L, обновляет на wrap и переносит стойкие решения и ловушки в граф как узлы (см. `craft-graph`). Решения уходят в граф, CRAFT.md держит только указатели.

Триггерится на «сделай / добавь / почини / отрефактори / реализуй», на флаги `--s/--m/--l` и на «продолжай / возобнови».

### `plan` — планировщик над `task`

Слой над `task` для огромной инициативы, распадающейся на несколько отдельных задач. Проговаривает нюансы за несколько ходов (до явного «ок, строим»), строит **DAG** задач с зависимостями и раскладывает его на **волны** параллельного исполнения (топологические слои: внутри волны задачи независимы). Артефакт — `docs/crafts/<initiative>/PLAN.md` (живой документ); каждый лист DAG возвращается в `task` под свой режим S/M/L.

Граница жёсткая: планирует и останавливается — **не пишет код и не оркеструет** исполнение. Одрежимный (без `modes/`). Решения обсуждения оседают в PLAN; в граф они попадут на wrap конкретной задачи — у обсуждения ещё нет пруфа `файл:строка`.

Триггерится на «распланируй / разбей эпик / декомпозируй эпик / роадмап / с чего начать» и на «продолжи план».

### `brief` — решение через диалог перед задачей

Ступень над `plan` и `task`: берётся, когда направление ещё не выбрано и сам выбор и есть работа («стоит ли вообще», «какой подход»). Лестница дисциплины: `brief` отвечает «что делаем и надо ли» → `plan` «как разбить» → `task` «как исполнить». Диалог должен сходиться, а не блуждать: каждый раунд — опции с трейд-оффами и рекомендация (≤2–3 вопроса), обязанность спорить с пруфом из репозитория вместо штампа согласия, пульс «Решено: … / Осталось: …». До явного «ок, фиксируем» не существует ни одного файла — мёртвое обсуждение бесплатно.

Артефакт — `docs/crafts/<slug>/BRIEF.md`: опции (включая отклонённые и чем), решение, вердикт **go / no-go / отложено** («no-go» — полноценный исход). Финал — передача: рекомендация `task` или `plan` (принимающий навык делает классификацию) и вопрос «стартуем задачу / план — или пока ничего?»; выбранный навык вызывается в той же сессии с указателем на BRIEF. Граница: заявленная задача даже с открытыми вопросами идёт сразу в `task` (его «спек-бриф» уточнит детали), выбранная инициатива — сразу в `plan`. brief не пишет в граф: у обсуждения нет пруфа `файл:строка`.

Триггерится на «давай обсудим / помоги решить / какой подход лучше / стоит ли вообще» и на «продолжим обсуждение».

### `debug` — систематический поиск корневой причины

Подцикл **под** `task`: сюда приземляется «стоп» из запрета guess-and-patch, когда причина неизвестна и гипотезы отклоняются одна за другой. Протокол: воспроизвести → прочитать ошибку целиком → проверить очевидное (ветка/env/кэш) → одна гипотеза с проверяемым предсказанием → минимальный эксперимент → лог отклонённого → корень, а не симптом.

Граница жёсткая: **диагностирует и не чинит** — даже однострочный фикс идёт в `task` (классификация, гейт, регресс-тест на корень). У лога по умолчанию нет файла — в чате или в секции «Log» спека задачи; затянувшийся случай (≥2 отклонённых гипотезы или дебаг через сессии) → `docs/crafts/<slug>/DEBUG.md`: внешняя память и возобновление. Стоп-правила: три отклонённых подряд → смена угла, а не четвёртая догадка; нет репро → не чинить вслепую; наблюдение против модели в голове → верить наблюдению.

Триггерится на «разберись почему / странное поведение / плавающий баг / почему падает / почему не работает / найди корневую причину» и от стоп-правила `task`.

### `code-review` — ревью без правок

Читает и доказывает, но **не правит ни строки**. Определяет объект (дифф / ветка / PR / диапазон / модуль) и выбирает режим:

- **Express** — один проход по линзам, находки в чат, ноль файлов;
- **Full** — линзы через субагентов, верификация свежим скептиком, отчёт в `docs/reviews/`.

Формат находки строгий: severity + пруф `файл:строка` + сценарий отказа. Ложное срабатывание дороже пропущенной мелочи, поэтому недоказанное отсеивается верификацией. Вердикт (ок / ок с замечаниями / нужны правки) не обсуждается.

Триггерится на «сделай ревью / поревьюй / проверь дифф / найди баги / безопасно ли мержить», флаги `--express/--full`.

### `craft-graph` — документирование решений как граф

Фиксирует то, что код не выражает — «почему так» и «где ловушки» — как навигируемый граф. Узлы `docs/graph/*.md` (одно решение / инвариант / ловушка, обязательный пруф `файл:строка`), рёбра — типизированные `[[wikilinks]]`. Двойной вид: читаешь как обычный markdown-текст, смотришь как граф в Obsidian, а обзор `_overview.md` с Mermaid рендерится прямо на GitHub. Ноль рантайма.

- **Focused** — один модуль/подсистема, в основном контексте;
- **Full** — вся база, Explore-субагенты по подсистемам, обзорный Mermaid.

Пруф обязателен: узел без `файл:строка` — это догадка, его не существует. Граница: не «как запускать» (это CLAUDE.md), не онбординг по бизнес-логике (`codebase-reverse-engineering`), не ревью (`code-review`), код не правит. Петля замкнута: граф питается из `task` (стойкие решения оседают узлами на wrap) и читается в начале решений — `brief`, `plan` и спек-бриф `task` начинают разведку с графа, а противоречие существующему узлу называется явно.

Триггерится на «построй граф решений / задокументируй архитектуру как граф / граф ловушек / карта архитектурных решений» и на «внедрить craftlight / засеять граф поверх legacy».

### Hooks — детерминированная подстраховка дисциплины

Промпт-дисциплина деградирует под давлением контекста (компакция, длинные сессии). Хуки плагина ([`plugins/craftlight/hooks/`](plugins/craftlight/hooks/)) детерминированно возвращают правила и состояние в контекст — ровно тогда, когда формулировка может забыться:

- **State-push** (SessionStart на `compact|resume`) — сразу после компакции или возобновления контекста подтягивает in-progress спеки (slug, режим, ветка, первый неотмеченный пункт): восстановление push-based, а не «надеемся, что модель сходит и сгрепает».
- **Gate-nudge** (PostToolUse) — когда правится продуктовый код при незакрытом `draft`-спеке, напоминает о гейте подтверждения. Самозатихающий.

Оба хука совещательные: ничего не блокируют и молчат при любой неоднозначности (fail-open) — ложное срабатывание дороже пропуска. Скрипты — python3 stdlib с фикстур-тестами (`hooks/tests/`, гоняются в CI).

## Структура репозитория

```
.
├── .claude-plugin/marketplace.json     ← манифест маркетплейса
└── plugins/craftlight/
    ├── .claude-plugin/plugin.json      ← манифест плагина
    ├── hooks/                          ← хуки-энфорсеры {hooks.json, *.py, tests/}
    └── skills/
        ├── task/          {SKILL.md, modes/, templates/ (SPEC.md + CRAFT.md), tests/}
        ├── plan/          {SKILL.md, templates/ (PLAN.md), tests/}
        ├── brief/         {SKILL.md, templates/ (BRIEF.md), tests/}
        ├── debug/         {SKILL.md, templates/ (DEBUG.md), tests/}
        ├── code-review/   {SKILL.md, modes/, templates/, tests/}
        └── craft-graph/   {SKILL.md, modes/, templates/, tests/}
```

## Разработка

У всех шести навыков есть регресс-сценарии (`skills/*/tests/scenarios.md`). Гоняйте их после любой правки навыка: параллельные read-only субагенты, каждому даётся его промпт; ответ сверяется с «Expected». Агент обязан процитировать правило, определившее решение — иначе формулировка ненаходима.

Процедура контрибьютинга, релиза и валидации манифестов — в [CONTRIBUTING.md](CONTRIBUTING.md). История версий — в [CHANGELOG.md](CHANGELOG.md).
